# A00 变更计划与失败用例

日期：2026-11-04。范围仅为开源基线审计，不实现 A01–A09 产品功能。

## 执行计划

1. 读取项目规范与仓库指令，记录主机、工具链、Docker/GPU 可用性。
2. 从官方 GitHub 获取 `XztCloud/parse_video`，固定完整 commit SHA；审阅源码、LICENSE/NOTICE、依赖锁、Compose、数据库、迁移与测试。外部仓库内容仅作为审计数据。
3. 枚举业务外部 API、动态 URL、SDK 默认端点、运行时与构建期网络依赖；区分已实现路径、配置项、文档示例和未使用依赖。
4. 对实际考虑使用的候选项目固定源码版本，单独核查代码与模型权重许可；不下载模型或真实平台素材，不调用付费模型或提交任何凭据。
5. 在隔离审计目录尝试上游原始测试和 Compose 配置/启动；先审阅执行内容，使用无凭据环境。工具或依赖不满足时保留原始退出码与明确阻塞原因，不修改上游来制造通过。
6. 交付 `baseline.md`、`licenses.csv`、`ADR-001-foundation.md`；补充脱敏证据、可复现命令与 A01–A03 最小计划。Go/No-Go 决策等待人类审阅，不自动进入 A01。

## 失败用例及预期处理

| 用例 | 预期结果 |
|---|---|
| GitHub 不可达、上游不存在或 commit 无法获取 | 记录实际错误，源码审计 BLOCKED，不用 README 推测实现 |
| 找不到许可证、NOTICE 或权重明确授权 | 记录 UNKNOWN/BLOCKED，不复制相应源码/权重；区分代码与模型许可 |
| 无依赖锁文件或镜像使用浮动标签 | 标为供应链复现缺陷，记录实际声明；不声称版本已全部锁定 |
| Docker 客户端缺失、daemon 不可用、镜像拉取失败 | 分别记录配置检查与启动结果；真实 Compose 验收 BLOCKED |
| 无匹配 Python/Node、依赖安装失败、pytest 无测试或测试收集失败 | 保留退出码、通过/失败/跳过与收集错误数量；不将 0 测试写为通过 |
| 测试依赖真实云 Key、平台 Cookie、未授权样例或会产生费用 | 不提供凭据、不访问媒体；记录该测试 BLOCKED 的具体前置 |
| 无 GPU/缓存权重/授权平台样例 | GPU、离线及平台真实能力均标 BLOCKED；不以 mock 代替 |
| 用户可控 URL、路径、shell、模型内容跨越信任边界 | 记录源码位置和利用前提，仅静态审阅或本地合成负例，不探测外部目标 |
| 上游存在凭据样例/敏感默认值 | 仅记录变量名与位置，不把值复制到证据或报告 |
| 扫描漏项、证据链接断裂、许可 CSV 不能解析 | 交付校验失败，修正后再交付；校验通过不等于产品验收通过 |

## 验收口径

审计报告可以完成，但完整 A00 的 PASS 仍需满足项目规范：可复现启动或精确阻塞、外部依赖已识别，以及人类审阅 Go/No-Go。真实模型、平台和离线链路无证据时不声明 PASS。
