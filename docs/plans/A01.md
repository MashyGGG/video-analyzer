# A01 本地基础设施：实施计划与失败用例

日期：2026-11-04。本文在 A01 实现前编写。依据 PROJECT_SPEC 第 3、7、9、11 章及 ADR-002。

## 范围与设计

- 新建 Next.js 状态首页、FastAPI、PostgreSQL、Redis、Celery；只实现基础设施状态和内部队列诊断，不实现上传、平台下载、媒体分析或登录业务。
- `/api/v1/health/live` 仅确认进程存活；`/api/v1/health/ready` 检查数据库、迁移、Redis；模型状态明确为 not_configured，不参与本阶段 readiness。错误不返回连接串、凭据或底层异常文本。
- Alembic 初始迁移创建 installation 表；不使用 create_all 或 stamp 掩盖空库问题。迁移服务成功后再启动 API/Worker。迁移支持 downgrade/upgrade，破坏性降级仅对隔离测试库执行。
- 默认仅将前端和 API 绑定 127.0.0.1；数据层和 Worker 只接内部网络。非 root 应用、只读根目录、临时目录和最小权限；Postgres、Redis、工作目录使用命名卷。
- 本地密码由脚本生成到被忽略的 secret 文件；不依赖模型 Key，不把凭据放进 Compose 输出、日志或证据。首次生成拒绝覆盖，重跑不轮换已有密码。
- Python 完整锁、npm lock、容器 digest 固定；登记实际依赖和许可。GPU overlay 只运行 NVIDIA 硬件诊断，通过 profile 显式选择，基础服务不需要 GPU。
- doctor.sh 提供 Bash 入口，由跨平台 Python 执行诊断：工具、版本、配置、CPU/RAM、GPU、服务健康；严格 GPU 选项明确失败，不以 mock 代替。

## 失败用例（先于实现）

| ID | 场景 | 预期 |
|---|---|---|
| F01 | 缺少 secret、空 secret、默认/弱密码 | 初始化/配置检查明确失败，不启动带默认口令服务；不输出密码 |
| F02 | 重新执行初始化 | 保留已有凭据；部分缺失/损坏时拒绝隐式轮换 |
| F03 | PostgreSQL 停止/密码错误/迁移版本不匹配 | live 200；ready 503，通用错误；恢复后自动就绪 |
| F04 | Redis 停止/密码错误 | ready 503；日志和 HTTP 响应不泄露连接串；恢复后可用 |
| F05 | 未配置模型/缺 NVIDIA | CPU 基础服务正常；模型显示未配置；GPU 严格检查 BLOCKED/非零 |
| F06 | 干净空库、重复 upgrade、downgrade 再 upgrade | 真实 Postgres 成功；重复 upgrade 保持 installation ID；隔离数据库降级不操作业务库 |
| F07 | 重启容器/重新创建容器 | 数据库 installation、Redis marker、/data marker 保持；验收结束清除测试 marker |
| F08 | Worker 不处理任务/Redis 中断 | 内部诊断有界超时并失败；真实 Celery 往返成功才计通过 |
| F09 | 未设置/设置假的第三方模型 Key | 均不改变基础服务；无第三方模型调用或权重下载 |
| F10 | 冻结依赖被更改、对外暴露数据端口、应用权限过大 | 锁校验/配置合同测试失败；不发布未测结论 |
| F11 | 前端 API 不可达 | 页面明确显示暂不可用；无伪造绿色状态；前端自身 live 可用 |
