# A01 补充：Playwright E2E 与基础设施复验计划

日期：2026-11-04。用户要求检索、深入分析前端、实现 E2E、重新验收 A01，并将结果汇总一份文档；以后每次前端更新都必须覆盖测试。本卡仍属 A01，不推进 A02/A07 业务。

## 阅读与检索后的设计

当前链路为浏览器 StatusPanel → Next `/api/health` → FastAPI ready → PostgreSQL/Redis；Worker 由 doctor/容器健康检查单独监控，models 固定 not_configured。首页不提供上传/分析入口。浏览器代码缺少响应合同校验、自身请求时限和轮询互斥；Next proxy 仅验证字段类型，可能把非 200/矛盾的 ready 透传为绿色状态。先用负例复现再修复。

采用官方 Playwright Test、role/name 定位、自动等待、独立 browser context、Clock 控制轮询时间、webServer 管理隔离端口，失败留截图/trace。参考：https://playwright.dev/docs/best-practices 、https://playwright.dev/docs/test-webserver 、https://playwright.dev/docs/clock 、https://playwright.dev/docs/ci-intro 。版本/授权使用官方 npm registry 和包内许可证固定，不把 mock 结果当真实模型/平台/基础设施成功。

分三类验证并分别报告：

1. 浏览器功能 E2E：真实 Next 生产构建 + 受控 `/api/health` 响应，覆盖加载/正常/各依赖故障/错误数据/网络错误/超时/轮询恢复/窄屏/刷新与导航；清楚标记响应 fixture。
2. Next proxy 合同：真实 Next HTTP 路由 + 仅测试用本地 HTTP fixture 服务，验证上游错误码、矛盾数据、非法 JSON、超时。fixture 不进入生产镜像。
3. 真实 A01：独立 Compose project/命名卷/端口运行真实 API/Postgres/Redis/Celery；浏览器不拦截健康接口，实际停止/恢复 API/DB/Redis 验证页面并执行已有迁移、队列、持久化等 25 项基础设施复验。结束恢复/停止本次隔离服务，不删除用户已有卷，不影响日常 3000/8000 实例。

最低浏览器矩阵为 Chromium 桌面与移动视口；不将移动视口说成真实手机或其他浏览器引擎。截图用于人工视觉检查；不通过自动接受快照来把 UI 错误标绿。覆盖指功能/失败场景覆盖，不虚构行/分支覆盖率。

## 首先编写的失败用例

| ID | 场景 | 应有结果 |
|---|---|---|
| E01 | 首个请求未返回 | 显示检测中，不显示已连接 |
| E02 | DB/Redis 任一失败 | 展示部分不可用，各卡片准确，API 仍可达 |
| E03 | API 网络不可达/HTTP 5xx | 不显示基础服务就绪或 API 正常；页面不崩溃 |
| E04 | null、缺字段、错误类型、未知状态或 ready 与依赖/HTTP 状态矛盾 | 安全降级，拒绝绿色状态；不暴露原始错误体 |
| E05 | 健康请求永久挂起 | 有界失败，随后可轮询恢复；不积累并发请求 |
| E06 | 请求慢于轮询周期/旧响应迟到 | 最多一个正在处理的请求；旧状态不覆盖新状态 |
| E07 | 15 秒周期、失败后恢复、刷新与首页链接 | 浏览器按实际逻辑更新，无脚本错误/外部请求 |
| E08 | 桌面与窄屏 | 三张卡片、模型未配置提示、标题可见，无横向溢出 |
| E09 | 真正停止 DB/Redis/API | 页面与实际 ready 状态一致；恢复后无需重新加载 |
| E10 | 前端变更漏跑测试或带 only/skip | 统一 verify 命令、仓库规则和 CI 阻止；测试失败使门禁非零 |
